**Vespertine now says when the equalizer can't change what's playing, comes with a reference equalizer for each USB-C AirPods Max model, and has its first multichannel result on real hardware.**

### Equalizer
- **It says when it can't apply.** The equalizer only changes PCM that Vespertine plays itself. Native DSD sent as DoP, Dolby and DTS bitstreams sent to a receiver, and Dolby Atmos that macOS renders all reach the output untouched, so turning an equalizer on for them changed nothing, and nothing on screen said why. Now, while one of them plays on an output that has an equalizer chosen:
  - the Equalizer window shows "Not applied" with the reason (for example, "native DSD (DoP) is sent untouched") and dims the preset's curve;
  - the output's equalizer setting shows the same note;
  - the signal path keeps an **Equalizer · bypassed** row with the preset's name and the reason, instead of leaving the row out.
- The sound doesn't change, and native DSD over DoP still shows **NATIVE DSD · DoP**, because its samples really are untouched.

### AirPods Max
- **A reference equalizer for each model.** Two editable presets are new: **AirPods Max USB-C (1st gen) — Reference** and **AirPods Max 2 — Reference**. When AirPods Max play over the USB-C cable, Vespertine reads the model's product ID over Bluetooth and uses the matching preset, unless you've chosen something else for them. Over Bluetooth alone nothing changes.
  - The first-generation curve starts from AutoEQ's published correction (Rtings measurements on a B&K 5128). The AirPods Max 2 curve makes smaller presence and treble changes, based on Headphones.com's B&K 5128 and on-head measurements. Fit and taste vary, especially above 3 kHz, so treat them as a starting point. Both are in the Equalizer window (View › Equalizer, ⌥⌘E) to adjust.
  - **Bit-perfect:** like any equalizer, the reference preset changes the samples. While it's on, 48 kHz music on AirPods Max over USB-C shows **EQUALIZER** instead of **BIT-PERFECT**. For bit-perfect playback, choose **Off** for the AirPods in the output's settings. If your AirPods were set to Off before, choose Off once more: earlier versions saved Off the same way as "never chosen", and this version keeps it as a choice of its own.
  - macOS may ask whether Vespertine can use Bluetooth. Vespertine uses it only to read the product ID of paired AirPods Max, to pick the matching preset.
  - Model detection hasn't yet been tried with either AirPods Max model connected.
- **Output settings fit on screen.** The output list in the bottom bar now scrolls when it's taller than its window, and an output's equalizer setting sits near the top of its settings, so it no longer drops out of view below the other options.

### Tested hardware
- **First multichannel result on a real device, reported by the developer:** a 2018 Sony TV over HDMI, with exclusive access:
  - 5.1 FLAC played with **BIT-PERFECT** shown, each channel on its matching speaker;
  - a 7.1 FLAC was folded into 5.1 and shown as **7.1 → 5.1**, not bit-perfect, because the TV has no 7.1 layout;
  - 5.1 DSD64 played converted to PCM and shown as **DSD → PCM**, since the TV doesn't accept DoP;
  - Dolby Atmos rendered by macOS also played (tentative).
- This is the app's own signal-path readout and the developer's report, not a capture of the samples at the TV. Receiver bitstream and channel-for-channel output to multichannel USB DACs remain untested on real hardware; [device reports](https://github.com/szeremeta1/Vespertine/issues/new?template=dac_report.yml) are welcome. Details and screenshots: [Tested devices](https://github.com/szeremeta1/Vespertine/blob/main/docs/DEVICES.md). The README, feature guide and website now say this instead of calling all multichannel output untested.

### Fixed
- **The website follows each release.** When 0.13.0 came out, vespertineapp.com's automatic update was refused by GitHub Pages, so the site kept the previous version and download link until it was republished by hand. A release now republishes the site from the main branch, which Pages accepts.

### Verification
- The engine, library and app test suites pass, including new tests for the equalizer's status on each kind of stream (a DoP stream keeps NATIVE DSD · DoP with the equalizer bypassed, and passes through an installed equalizer word for word, while PCM is changed by it) and for the AirPods Max product IDs and presets.
- Checked in the app on a virtual loopback output with DoP enabled: native DSD shows the note, the dimmed curve and the "bypassed" row; FLAC shows the full curve and "Equalizer · on".
- Not yet checked: AirPods Max model detection on either model, and the website republishing on a real release (it runs for the first time with this one).

### Known issues
- A stray icon can appear next to the sidebar button while the search field is active.
- If you delete one of the AirPods Max reference presets, it comes back the next time Vespertine opens, and plays on those AirPods again unless you've chosen Off or another preset for them.
- When AirPods Max use their reference preset automatically (you haven't picked it yourself) and macOS renders Dolby Atmos to them, the Equalizer window and the signal path don't say the equalizer is bypassed.

### Install
Download **Vespertine-0.13.1.dmg**, or let Vespertine update itself. Requires macOS 14.4 or later on Apple silicon or Intel. Signed with a Developer ID, notarized and stapled. Homebrew: `brew upgrade --cask vespertine`.
